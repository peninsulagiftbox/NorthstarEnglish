# 响应式验收

使用同一Chrome会话、100%截图比例、前后两个独立Next production构建。真实合成账户与数据分别固定为空复习队列和有真实错误尝试的队列，不使用API响应mock。两个构建各81个检查组合：11个受保护界面×6尺寸=66，3个有数据界面×3尺寸=9，以及登录/注册×6尺寸（以6个auth组合记录）。

有数据复习/Quiz/报告另测1440×900、768×1024、390×844，概念队列保持相同工具栏间距；真实概念卡有5条来源，未通过UI自评改变调度以制造截图。

定量检查由scripts/ui/capture.js收集DOM BoundingBox、scrollWidth/clientWidth；scripts/ui/validate-layout.py执行断言：

- 75个受保护页面组合的main、shell和视口没有横向溢出；6个auth组合的内部滚动容器无横向溢出。
- 工具栏子项不超出父容器，按钮之间无交叠；卡片直接内容不越过边界。
- 页头与主内容不交叠，Tabs与内容面板至少16px（含既有提示行时可更大）。
- 空/有数据概念队列的工具栏与首面板精确为24/20px。
- 主滚动区到底后，分页说明不裁剪，播放器不覆盖末尾同步说明。

不是对任意两个DOM元素机械要求24px。本次没有发现P0，修复的贴靠属于P1，并非所有贴靠都能由“元素交叠”断言捕获。

额外用640×450的CSS视口模拟1280×900在200%缩放后的布局空间，复习页面可用；未声称执行了所有操作系统/浏览器的原生缩放、Safari、实体手机或麦克风权限。真实注册、设置提交、Tab键盘顺序及来源弹窗另有生产交互证据。
