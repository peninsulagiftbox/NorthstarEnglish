# Northstar English｜Codex 正式开发提示词 V1.0

> 使用方式：把本包 `references/phase1/` 复制到你的项目根目录 `references/phase1/`；在项目根目录启动 Codex。**先提交 Prompt 00，待你批准实施计划后，再每次提交一个 Phase Prompt。** 不要一次把全部阶段丢给 Codex。
>
> 产品约束：个人自学、Mac 本地、桌面 Web 优先；四册《新概念英语》只做课程目录框架，不导入未获授权的教材课文或音频；可学内容先只有原创 Demo 01 *The Neighborhood Garden*（10 句）。

## 全阶段共同约定（由 Codex 创建在项目 AGENTS.md 并遵守）

1. 每轮先阅读 `docs/IMPLEMENTATION_PLAN.md`、`references/phase1/` 中适用文件、`docs/progress/` 最近阶段报告，并核对 `git status`。不存在的文件如实说明。
2. 使用 **Next.js App Router + TypeScript + Tailwind CSS** 作为前端，**Java 21 + Spring Boot + MySQL 8 + Flyway** 作为后端，除非经现有项目核查后提出并获得同意的替代方案。单人本地项目，不上微服务；Redis、账号、多租户、支付和云服务均非一期依赖。实际依赖版本采用兼容且受维护版本，并提交锁文件和版本依据。优先复用现有仓库。
3. 保留原型桌面交互与视觉基准（1440×900、约 224px 左导航、主学习区/右侧句子助教约 2:1、约 76px 底部播放器）；将静态 HTML 重构成可测试组件，**不得通过 iframe 嵌原型或用整块 innerHTML 伪装正式完成**。
4. 第一阶段以原创 10 句及其合法合成音频为唯一可学内容；其他四册为 `catalog_only`。内容必须具有来源/授权字段，不得抓取或批量复制有版权的课文/录音。
5. 数据必须区分 `not_started`、`in_progress`、`practiced`、`skipped`、`paused`；`practiced` 必须有真实尝试证据，不能仅按浏览、播放或按钮点击计数，更不能把跳过当完成。
6. 每条真实作答、听写、测验和复习记录都关联到 `lessonId`，适用时关联 `sentenceId`、`knowledgePointId`、`exerciseId`；事件带不可重复 `eventId`，后端幂等入库。草稿与正式提交分离，练习/写作版本可追溯。
7. 没有实际接入 AI、ASR 或专业语音评测时，必须明确标记“本地预置讲解”“录音回放/人工自评”，禁止虚构模型反馈、语言能力分、音素评分。AI 失效不得阻塞学习。
8. 个人本地运行也不能在浏览器放 API Key。DB 密码放 `.env`（仅提交 `.env.example`）。避免 `0.0.0.0` 对外暴露无身份验证的写接口；开发服务尽可能绑定 `127.0.0.1`。
9. **不得更改已有全局 Node/Java 版本，不得删除或重建已有 MySQL 数据、Docker 卷、已有项目目录。** 检测端口冲突后选择可配置端口（例如本项目 MySQL 使用 `127.0.0.1:3307`，如被占用自动调整并记录）。禁用危险清理命令。
10. 一阶段一提交范围，不提前开展后续阶段；改动前审查影响，尽量小步实现，避免不必要依赖。发现无法满足的验收条件，报告阻塞原因而不是模拟通过。
11. 阶段结束必须执行实际可运行的编译/类型检查、单元或集成测试、必要的 Playwright E2E；自动化失败需保留日志及原因，**不能声称未跑过的测试通过**。对浏览器麦克风权限等自动化难覆盖项目，提供手工步骤并明确未测。
12. 每阶段把结果写入 `docs/progress/PHASE_XX.md`：改动文件、关键设计决定、运行命令与结果、通过/未通过的验收条目、未解决问题、截图位置、下一阶段依赖。汇报后停止，等待我的审核。

## Prompt 02｜原创课程入库、内容版权与课程 API

在 Phase 01 验收后，执行 Phase 02，除此之外不改业务模块。

开发：
1. 从 `english_lab_desktop_prototype.html` 提取原创 Demo 01 *The Neighborhood Garden* 的 10 句对话、对应中文、说话者、上下文讲解、词汇、标准答案及内嵌 MP3。编写可重复执行的提取/校验脚本；不要用不可信的 `eval` 运行整块原型代码。
2. 将 base64 MP3 转为独立音频资源（命名稳定）；检测文件格式、大小、实际时长并计算 SHA-256；校验 10 条句子和 10 个音频是一一对应。不要通过英语文本长度猜测音频时间戳。只有逐句音频时，`startMs=0,endMs=duration` 即为局部时间轴。
3. 给原创内容建立 `sourceType=original` 的授权记录、内容版本与素材来源说明；内嵌的教学释义亦作为预置教学内容，未授权的四册课文/录音完全不导入。

6. API 添加异常与缺失资源处理：未知 lesson 返回规范化 404；音频丢失返回明确错误而非伪造播放成功。

验收：数据库清楚显示唯一合法原创课及四册占位；一次 API 调用可以获得真实的 10 个句子和音频 URI；10 个音频实际能请求和播放；二次播种不增加行数；不存在未经授权教材正文；单元/集成测试通过。写 `PHASE_02.md` 并停止。

## Prompt 04｜真实音频引擎、逐句复读、精听听写

在 Phase 03 验收后执行。**这是核心体验，优先正确性、时间轴与防剧透。**

开发：
1. 将 Demo 01 的 10 个合法 MP3 连接至工作台播放器。统一 audio controller，防止多播放器同时争抢；支持按句播放、播放/暂停、上一句/下一句、连播、单句循环、变速 0.75/1/1.25/1.5，播放进度真实可拖动。`Space`/`J`/`K`/`R` 快捷键生效；输入框焦点下不截获。
2. 对有真实音频时长的单句文件实现句内 A-B 复读，可选 A/B、取消和循环，校验 `0 <= A < B <= duration`；无可靠时间轴时隐藏相关功能而不是伪装。不要宣称已有贯穿全课的连续波形同步。
3. 媒体异常处理：自动播放限制、加载失败、切换句子的 pending 状态、播放 Promise 拒绝、资源损坏、播放结束、切 Tab 和卸载时清理。全局底部播放器视觉状态与实际音频播放一致。
4. 听写页面实现输入与草稿自动保存（按 lessonId + sentenceId），正确答案在提交前不展示在当前工作区、右侧助教或辅助属性中。保留用户原始输入。
5. 实现可解释的文字对比：大小写及标点可容忍；基于英文 token 序列做对齐，区分遗漏、插入、替换；标准写法与用户输入并排展示。选择题判分方式不能用于听写，不要把同义词随意判为准确听写。
6. 非空提交写入 attempt + `learning_evidence`，包含 eventId、lessonId、sentenceId、结果、原始文本、对齐差异；错误触发关联来源的复习项目，接口重试不可生成重复事件/卡片。跳过记录 `skipped`，不得增加 practiced。

验收用例：第 6 句故意输错 `beside`，显示准确错误位置且保留原文，能回听第 6 句、复习列表有来源；重复相同 eventId 不重复入库；刷新恢复草稿；空白不可提交；键盘在输入区不触发播放；断开音源后显示故障且不会误判已做题。要求单元、后端接口、Playwright E2E 实测。写 `PHASE_04.md` 并停止。

## Prompt 06｜口语跟读录音、写作草稿与历史版本

在 Phase 05 验收后执行；此阶段不做模型语音评分。

开发：
1. 实现录音状态机：idle → requesting_permission → recording → processing → ready / failed / denied。使用 `MediaRecorder` 及 getUserMedia，在 localhost 安全上下文工作；选择句子后可先听原音，再录音、停止、回听、重录。录音停止与页面卸载需释放麦克风轨道、对象 URL。
2. 记录必须绑定 lessonId + sentenceId + createdAt + MIME 类型 + 时长。设计本地稳定保存策略（例如私有本地磁盘 API 存储文件并记录数据库元信息；或在用户明确选择后保存到 IndexedDB），必须可查询、删除；不能把录音塞入 localStorage，也不能假装关闭页面后还在。对于不能跨重启恢复的临时录音，明确标注。
3. 权限拒绝、浏览器无支持、设备断开、录制失败时显示原因，可重试/跳过，不阻止其他学习；用户无可回放录音时不能标记口语 `practiced`。
4. 不接 STT 时只能自评与回放，不出现“发音 95 分”；后续 STT 与专业发音评测预留接口但不必实现。
5. 写作 Tab 为原创任务：`Write 2–3 sentences about helping in a garden. Use please, beside, or I can ...`。提供非空草稿自动保存、V1/V2/... 不可变版本、版本列表、内容对比和基础规则提示；规则检查明确非 AI 语法校对。
6. 保存版本应由服务端生成递增版本号、处理并发/重复提交；草稿与已保存版本分离。编辑历史不覆盖，删除操作需二次确认。

验收：许可麦克风时录制/停止/回放，重新打开可按约定访问持久录音；拒绝权限时跳过且不计完成；作文写出两版后刷新能看到 V1/V2 且内容不被覆盖；服务重启数据不丢。浏览器权限相关未自动测试项目必须记录人工实测步骤。写 `PHASE_06.md` 并停止。

## Prompt 07｜课时测验、错题复习与间隔调度

在 Phase 06 验收后执行。重点是完整“学习 → 错误 → 到期复习 → 复测”的链路。

开发：
1. 将 Demo 01 的 3 道原创测验题从原型迁入数据库，固定题目/选项/答案版本，提交时记录题目、选择、是否正确、源句或知识点及 attempt 时间。多次重做保留历史；不要只保存最近得分。
2. 错答产生可追踪的 `learning_evidence`，创建或更新 `review_item`，唯一性依据设计说明，避免重复点击无限新增同一张卡；允许同一句因不同错误类型产生不同知识点的复习任务。
3. 复习页真实读取到期数据；卡片在翻开前遮挡答案，点击“忘了/记住”写入复习历史并更新下次到期。初期明确使用简化调度策略（例如忘了：1 分钟；记住：1 天，之后按成功次数增长），不冒称 FSRS 或复杂算法。
4. 日期时间以 UTC 存储、浏览器本地时区展示；同一个操作重试必须幂等。空队列显示正确空状态，不造样例卡。
5. 为每张卡增加“来自哪节课/哪句/哪次错误”的跳转，可以回到原句重学。跳过题目的用户不得获得复习成功计数。

验收：故意答错课程第 6 句关联题目 → 新复习任务出现 → 翻卡 → 选“还不会” → 查看新的到期时间 → 服务重启后状态存在 → 可返回第 6 句；重复提交不能重复产生记录。包含后端集成与 E2E。写 `PHASE_07.md` 并停止。

## Prompt 08｜学习报告、设置、数据导出与 AI 教师可选接入

在 Phase 07 验收后执行。优先做数据可信与备份，AI 的外部模型接入可作为独立的可选子任务：**不能为接 AI 牺牲核心闭环的稳定性**。

开发：
1. 首页“继续学习”和六阶段状态完全来自真实服务端数据；显示 `not_started`、`in_progress`、`practiced`、`skipped`，依据最近 session 恢复课程/Tab/句子。
2. 报告页只显示已产生的数据：听写实际提交次数/完全匹配数、阅读题作答记录、录音次数、写作保存版本、测验正确/总题、到期复习等；各指标标注分子/分母和样本量，没有训练或复测时显示“暂无数据”，不得虚构四技能能力雷达图。
3. 设置页持久化译文显示、默认播放倍速、键盘提示等偏好；实现 JSON 导出学习记录、作文历史、课程进度、复习信息和数据版本。导入前严格校验格式、版本与归属，提供预览/备份，不能静默覆盖现有数据。录音文件单独列出备份策略，不在导出 JSON 里假装包含二进制内容。
4. 对所有删除/清空加入确认与范围说明，数据库备份/恢复脚本不能使用危险的无条件清卷操作；部署绑定本地回环地址，避免未经授权开放写 API。
5. 句子助教先确保通过 `lessonId + sentenceId` 查询预置讲解、用法和原创例句，切句不串课。提供“AI 未启用”明确状态。
6. **仅在 `.env` 提供有效模型服务配置时**接入可替换的 AI 后端适配器（OpenAI-compatible 等以实际供应商文档为准）；API Key 只在服务器；调用超时、失败与用量上限；模型回复通过受限结构验证及 `sourceSentenceIds` 当前课校验，不通过时返回预置讲解/无法验证说明。不得把模型自由回答伪装成教材权威内容。
7. 将 AI、录音等外部成本能力放进开关；默认无外网 API 也能完整学课。

验收：刷新重启后首页/报告反映真实数据库；空数据不出现编造百分比；导出/导入演练可正确恢复并校验一致性；无模型 Key 时讲解仍可正常使用；有 Key 时只回答当前课相关的测试问题，对错课引用和注入指令能拒绝或降级。将 AI 未完成部分如实记录。写 `PHASE_08.md` 并停止。
